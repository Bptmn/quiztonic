## QuizTonic

**Repository**: [https://github.com/Bptmn/quiztonic](https://github.com/Bptmn/quiztonic)

![Flutter CI](https://github.com/Bptmn/quiztonic/workflows/Flutter%20CI/badge.svg)

QuizTonic is a Flutter mobile and web app (built with FlutterFlow) that turns your content into interactive quizzes powered by an AI API. Users can paste raw text, a website URL, or upload a PDF; the app calls a serverless AI endpoint that returns structured JSON describing questions and optional flashcards. Quizzes are then presented with scoring, timing, and progress tracking. Authentication and data persistence are handled by Firebase.

### Overview

QuizTonic turns user content (raw text, URLs, PDFs) into interactive quizzes and flashcards using an external AI API. The app targets mobile (iOS/Android) and web with a shared Flutter codebase and Firebase backend for auth, storage, and analytics.

### Main features
- **Multi-provider authentication**: Email/password, Google, and Sign in with Apple (iOS).
- **Content ingestion**: Raw text, URL, and PDF-to-binary support to generate quizzes.
- **AI-generated quizzes**: Calls a serverless API that returns structured question cards and flashcards.
- **Quiz experience**: Multiple-choice questions, per-question feedback, optional timer, score tracking.
- **Flashcards**: Review generated flashcards as a complementary study mode.
- **Library and folders**: Store and organize past quizzes; revisit results.
- **Statistics**: Track totals like quizzes taken, questions answered, correct answers, and time spent.
- **Credits/subscription model**: Store per-user credit count for controlled usage.
- **Settings & profile**: Manage profile, language, security, subscription, and feedback/contact.

### Tech stack
- **Flutter 3.x** with **Material 3** theming (generated by FlutterFlow)
- **State management**: FlutterFlow `FlutterFlowModel` and Provider
- **Backend-as-a-service**: Firebase Authentication, Cloud Firestore, Cloud Storage
- **Payments/subscriptions**: RevenueCat via custom actions and FlutterFlow helpers
- **Serverless AI API**: HTTPS AWS Lambda URL for content-to-quiz generation
- **Notable packages**: `http`, `google_fonts`, `font_awesome_flutter`, `flip_card`, Firebase libraries

### Architecture & project structure

High-level layout of the main Flutter app:

- **`lib/`**
  - **`auth/`**: Authentication abstractions and Firebase implementations (email, Google, Apple, anonymous, phone, JWT). Entry points include `auth_manager.dart` and `firebase_auth/firebase_auth_manager.dart`.
  - **`backend/`**: Firestore models, querying utilities, Firebase config, and API client.
    - **`api_requests/`**: `api_manager.dart` (HTTP client with multipart support) and `api_calls.dart` (AI generation endpoint wrapper).
    - **`schema/`**: Firestore record classes and structs for `users`, `my_quiz`, `my_folders`, `my_statistics`, `my_subscription`, plus value types like `QuestionCardStruct` and `FlashcardStruct`.
    - **`firebase/`**: `firebase_config.dart` bootstraps Firebase on mobile/web.
    - **`firebase_storage/`**: Upload helpers for files.
  - **`components/`**: Reusable UI widgets such as `QuestionCard`, `AnswerItem`, `ItemFlashcard`, list tiles, loading and empty states.
  - **`dialogs/`**: Reusable dialogs (create/edit folder, password check, pick folder, reset password).
  - **`flutter_flow/`**: Generated utilities and widgets: theming, navigation, localization, timers, request manager, revenuecat helpers, etc.
  - **`main_pages/`**: Feature pages (quiz generation, quiz runner, answers review, score, loading view, flashcards).
  - **`tab_pages/`**: Bottom navigation tabs (home, library, profile).
  - **`settings_pages/`**: Profile editing, language, legal, security, subscription, support/contact, feedback.
  - **`custom_code/actions/`**: Custom actions (PDF to binary, clipboard paste, URL normalization, RevenueCat integration, Firestore ID generation, etc.).
  - **`app_state.dart`**: Global app state, including request managers.
  - **`app_constants.dart`**: Shared constants (e.g., layout max width, initial credit values).
  - **`main.dart`**: App entry point, Firebase init, routing, and root `MyApp` widget.

### User flow

1. **Onboarding & authentication**  
   The user opens the app and logs in via email/password, Google, or Apple. On first login, a user document plus default stats/subscription are created in Firestore.
2. **Home & library**  
   The home/library views display folders, previous quizzes, and basic statistics.
3. **Generate quiz**  
   On the generate page, the user selects the content source:
   - Paste raw text
   - Enter a URL (normalized)
   - Upload/select a PDF (converted to binary)  
   They can configure options such as number of questions, number of choices, and whether to generate flashcards.
4. **AI request**  
   The app calls the AI API via `AiContentGenerationApiCall`, sending the structured payload. A loading page is shown while waiting for the response.
5. **Persist results**  
   On success, the response is mapped to `QuestionCardStruct` and `FlashcardStruct`, then stored as a `MyQuizRecord` under the current user, optionally inside a folder.
6. **Take the quiz**  
   The user answers questions one by one. Each question locks after selection, stores `userSelectionIndex` and `questionIsDone`, and can display explanations.
7. **Scoring & review**  
   When finished, the score page shows overall performance (number of correct answers, time, etc.) and updates aggregate statistics (`nbQuizDone`, `nbQuestionsDone`, `nbCorrectAnswers`). The user can later review answers and flashcards from the library.

### External API dependency

The mobile app delegates quiz and flashcard generation to a separate backend project, **QuizTonic API**.

- **Repository**: [https://github.com/Bptmn/quiztonic_api](https://github.com/Bptmn/quiztonic_api)
- **API contract**: `API_CONTRACT.md` in the API repository documents the exact request/response schema.

#### Current endpoints

- **Production**  
  `https://2mmjiwjyo27dfsa227qdc67jue0drajz.lambda-url.eu-west-1.on.aws/`

- **Development**  
  `http://localhost:5050`

The main app uses `lib/backend/api_requests/api_calls.dart` to call the AI endpoint. A typical call looks like:

```dart
final response = await AiContentGenerationApiCall.call(
  url: 'https://example.com/article',
  numOfQuestions: 10,
  numOfChoices: 4,
  generateFlashcard: true,
);
```

The request body is a JSON object with a nested `data` field containing:

- `text_content` (optional string)
- `url` (optional string)
- `pdf_file` (optional base64 string)
- `num_questions` (required number)
- `num_choices` (required number)
- `generate_flashcards` (optional boolean)

The API responds with quiz metadata (`quizName`), a list of `questionCards`, optional `flashcards`, and a `quizContext` payload (content source, language, token and cost metrics).

The API URL is currently hardcoded in `lib/backend/api_requests/api_calls.dart`. For production deployments, consider:

- **Environment variables**: Use Flutter `--dart-define` flags to inject the base URL.
- **Firebase Remote Config**: Allow the backend URL to be updated dynamically without publishing a new app build.
- **Config file wrapper**: Centralize the base URL in a small `ApiConfig` class imported by the API call layer.

### Running the project

#### Prerequisites

- Flutter 3.x installed (`flutter doctor` clean)
- Dart SDK bundled with Flutter
- Xcode (for iOS) and Android Studio/SDK (for Android)
- A configured Firebase project with the matching iOS/Android/Web configs

#### Install dependencies

```bash
flutter pub get
```

#### Run on mobile

- **Android**:
  ```bash
  flutter run -d android
  ```
- **iOS** (simulator):
  ```bash
  flutter run -d ios
  ```

#### Run on web

```bash
flutter run -d chrome
```

Build artifacts for production (web, Android, iOS) follow the standard Flutter commands:

- Web: `flutter build web`
- Android: `flutter build apk` or `flutter build appbundle`
- iOS: `flutter build ios`

### Environment & configuration

- **Firebase**  
  - Web configuration is defined in `lib/backend/firebase/firebase_config.dart`.
  - Native platforms use the standard `google-services.json` (Android) and `GoogleService-Info.plist` (iOS) files.

- **AI API URL**  
  - Currently configured directly in `lib/backend/api_requests/api_calls.dart`.
  - Recommended to wrap this into a dedicated config layer and/or Firebase Remote Config for environment switching.

- **Credits & subscriptions**  
  - Backed by Firestore collections and `MySubscriptionRecord`.
  - RevenueCat is integrated through custom actions provided by FlutterFlow utilities.
